# NATS Bonus Creator — Changelog

| Version | Date | Summary |
|---|---|---|
| v2.21 | Aug 9, 2026 | **Hotfix: v2.20 Casino Game regex broken by template escaping** — the v2.20 ™-tolerant game matcher was written with single backslashes (`\s`, `\(`, `\)`) inside the JS template literals that generate the Python scripts; JS template rendering swallows single backslashes, so generated scripts compiled the regex as `^...™?s*(MI)$` instead of `^...™?\s*\(MI\)$` and never matched any dropdown option (15s timeout at game selection while the correct options were visibly listed). Backslashes doubled in all three pattern functions (RTC FS / RAF / SUO). Fix verified end-to-end: each template's pattern function was extracted from the HTML, rendered through a real JS template literal via node, executed in Python, and the compiled regex tested against `Triple Cash Eruption™ (MI)` (match), the pre-update non-™ name (match), and wrong jurisdictions including `(ON)` (reject). v2.20 should not be used — any scripts generated from it will fail at Casino Game selection. |
| v2.20 | Aug 9, 2026 | **Casino Game selection made ™-tolerant (RTC FS / RAF / SUO)** — NATS renamed casino games to include a trademark symbol (e.g. `Triple Cash Eruption` → `Triple Cash Eruption™ (WV)`), which broke game selection in all three free-spin flows: scripts typed `{searchName} ({jurisdiction})` into the search box, and the `™` sitting between the name and the jurisdiction suffix caused zero search results, followed by a 15s exact-match timeout. Game selection now works in two parts: **(1) Search** — scripts type only the portion of the search name before any `™` (`Triple Cash Eruption`, `7's Fire Blitz`, `WrestleMania`), surfacing every variant regardless of how NATS renders the symbol; **(2) Match** — the dropdown option is chosen with an anchored regex where every `™` is optional (both mid-name and trailing) but the jurisdiction suffix is required, so the correct state's game is always selected whether or not NATS includes `™`, and wrong jurisdictions or similarly-named games can never match. `parse_casino_game()` replaced by `parse_casino_game_search()` + `parse_casino_game_pattern()` in the RTC FS, RAF, and SUO templates. Terminal output now prints the actual option text NATS displayed (e.g. `Casino Game: Triple Cash Eruption™ (WV)`). The `GAMES` table is unchanged — no search-name edits are needed for the four existing games, and the matcher is resilient if NATS adds or removes `™` again. Matching logic validated against 10 unit tests covering old naming, new naming, wrong-jurisdiction rejection, and similar-name rejection. |
| v2.19 | Aug 9, 2026 | **Free-spin offer types made currency-aware** — RTC FS, RAF, and SUO Day 2+ spin-value selection updated to match the v2.18 RTC CC pattern. The Free Spin Stakes table row is now chosen dynamically via the `currency_for()` helper (already embedded in every template since v2.18) instead of a hardcoded `USD` label anchor: RTC FS derives currency from the code name; RAF and SUO derive it from the script's `JURISDICTION` constant. US/MI/WV/PA/NJ → **USD**, ON/AB/CA → **CAD**, GBP unreachable. Behavior is unchanged today since all three offer types are restricted to MI/NJ/WV/PA (always USD) — this future-proofs the flows for any Canadian free-spins expansion with no further code change beyond allowing the jurisdiction in the UI. Terminal output now prints the selected currency (e.g. `Spin Value (USD): $0.20`). |
| v2.18 | Aug 9, 2026 | **NATS multi-currency amount tables** — a NATS update added a currency dimension to the bonus amount tables: what was a single amount input is now a three-row table with one row per currency (`USD` / `GBP` / `CAD`), each keyed by `data-row-key` on the `<tr>`. The old page-wide selector (`td.ant-table-cell.center` → `input[aria-valuemin='0']`) now matches 3 elements and crashes with a Playwright strict mode violation (first observed on an RTC CC bonus build, Aug 9). All generated scripts now include a shared `currency_for(name)` / `fill_currency_amount()` helper: jurisdiction is derived from the code name (US/MI/WV/PA/NJ → **USD**; ON/AB/CA → **CAD**; **GBP is never used under any circumstance**) and the amount is filled via `tr[data-row-key='{currency}']`, with a fallback to the legacy single-input selector if NATS ever reverts. Patched fill sites: **RTC CC** Casino Credit amount, **LC-REACT** Casino Credit amount, **BG** FanCash amount, **DM** Bonus amount + Minimum/Maximum Deposit cards, **LC-CHURN-DM** Bonus/Casino Credit amount card + Minimum/Maximum Deposit cards. The DM and LC-CHURN-DM card fills previously used `.first`, which would not have crashed but would have silently filled the **USD row for Canadian jurisdictions** — now fixed. RTC FS / RAF / SUO free-spin fields are label-scoped form items, not amount tables, and are unaffected; their USD-only jurisdictions mean any `.first` card fills still land on the USD row. Percentage inputs (`aria-valuemax='100'`) are not part of the currency table and are unchanged. |
